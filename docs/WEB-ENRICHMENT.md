# TechDigital public-source enrichment · AliceLabs LLC

## In the published browser workspace

Load a CSV, map company and website columns, accept the network notice and click
**Enriquecer lista**. Up to 100 selected rows are queried sequentially per run.
Wikidata returns candidate entities; GLEIF returns legal entities with LEIs.
Confirm the actual company before attaching its observed fields. A name alone is
not identity proof. Missing data is left empty. Provider failures remain visible.

For supplied or confirmed websites, Google Public DNS returns MX, SPF and DMARC
observations. A null MX explicitly means the domain declares no email; missing MX
is not proof of an invalid mailbox (SMTP may use an implicit A/AAAA fallback).
No SMTP check runs inside the browser. SPF/DMARC observations are not full audits.

Export contains every original row and column plus separate ENRICH_* columns:
observations, source URLs, timestamp, conflicts, errors and processing status.
Original contact values are never overwritten. Rows outside the run limit retain
not_processed. Clearing/loading/remapping cancels pending requests and results.
No contact patterns or employee counts are generated by an AI.

Queries disclose company names to Wikidata/GLEIF and domains to Google, plus
ordinary connection metadata. No full CSV is uploaded. No public proxy is used.
Provider access, CORS and quotas can change; a zero-cost source is not an SLA.

## Extract actual published website contacts

GitHub Pages cannot run Python or fetch arbitrary websites across browser CORS.
`enrichment_service.py` supplies the crawler separately. It is NOT deployed by
publishing the static website. Use an existing Python-capable server behind TLS.

```
python -m pip install aiohttp
# Set PROSPECT_SERVICE_TOKEN to a randomly generated 32+ character secret.
# Set PROSPECT_ALLOWED_ORIGIN=https://techdigital.site
python enrichment_service.py
```

Default bind is 127.0.0.1:8081. Proxy that port through your HTTPS server. A container
recipe is included at deploy/Dockerfile.enrichment; bind it to loopback on the host
and terminate TLS in the existing proxy. Keep the token in server secret settings,
never in a commit or public JavaScript. On the site open “Extracción de sitios web”,
enter your HTTPS service origin and token. They remain only in the current tab.

The endpoint POST /api/enrich accepts one website, a Bearer token and the configured
Origin. It returns published mailto/tel links, description and source URLs. It has:
actual public-IP DNS validation; no redirects; robots.txt checks (fail closed on
unavailable policy except 404); same-origin crawl; 3-page and 512 KB/page bounds;
35s job timeout; at most 2 concurrent jobs and 20 starts/minute per instance.
No access logs, contact cache or job database are enabled by this service. Hosting
providers may still collect infrastructure logs. Use per-user tokens/quotas and
persistent abuse controls before turning it into a multi-tenant public service.

A redirect is returned as site_http_301/302 rather than followed; supply the
confirmed canonical HTTPS website and retry. The crawler never bypasses a login,
CAPTCHA, robots exclusion or access block. No message is sent to any contact.

## Sources and realistic coverage

- Wikidata structured facts: https://www.wikidata.org/wiki/Wikidata:Data_access
  and https://www.wikidata.org/wiki/Wikidata:Licensing (CC0 structured facts).
- GLEIF legal identities: https://www.gleif.org/en/lei-data/gleif-api/ . Coverage
  is entities with a LEI, not every local business. Not a contact database.
- Google DNS JSON: https://developers.google.com/speed/public-dns/docs/doh/json .
- Company websites: actual public contact links only, subject to site policy.
- Hunter has API/free-plan access but requires an account/key and limited credits:
  https://help.hunter.io/en/articles/11060999-what-s-included-in-hunter-s-free-plan .
  It is not silently used with another user's key or described as unlimited.

This is file enrichment, not an Apollo-sized private contact database. Small
businesses absent from public registries need a supplied website plus the crawler
or a separately licensed discovery provider. SMTP validation remains available in
the desktop operator. Do not call missing contact data a verified lead.
